# 发票批量查验（全国增值税发票查验平台）

在国家税务总局全国增值税发票查验平台上批量查验发票台账中的全部发票，自动完成填表→验证码识别→提交→结果判定→截图，最终输出带截图的 HTML 查验报告。

## 适用场景

- 用户提供发票台账（CSV/Excel），要求在官方平台查验真伪
- 需要逐张保存查验结果截图并汇总成报告
- 关键词：发票查验、查验发票、发票真伪、发票台账核验

## 平台与前置知识

查验平台为 Vue/TDesign 应用，表单结构、验证码机制、金额/校验码规则、票种限制、限流策略等关键细节见 `references/platform-notes.md`。**执行前必读该文档**，它记录了实战踩坑结论（如数电票"伪发票代码"问题、老式税控票需校验码、区块链发票不可查验等）。

## 工作流

### 0. 环境准备（首次运行）

```bash
node scripts/setup_env.mjs
```
安装 playwright + chromium，并创建 python venv 安装 flask/opencv/numpy/ddddocr。幂等，可重复运行。

以浏览器实际启动成功和 OCR `/health` 返回 `ok: true` 为就绪条件。Windows 安装与进程恢复细节见 [平台注意事项第9节](references/platform-notes.md#9-windows-批量查验排障与恢复2026-11-03复盘)。已有环境优先自检后复用。

### 1. 解析台账

```bash
node scripts/parse_ledger.mjs <台账.csv> <工作目录>/invoices.json
```
- 自动检测 GBK/UTF-8/GB18030 编码，按列名别名匹配字段（发票号码/开票日期/发票代码/价税合计/校验码等）。
- 输出 `invoices.json`，每条含 seq/type/date/code/number/seller/amountNoTax/tax/amountTotal/checksumCode。
- 确认控制台输出的"按类型"统计，留意区块链发票、纸质车票等不可查验票种的数量。

### 2. 启动 OCR 服务（常驻）

```bash
python scripts/ocr_server.py 8731
```
验证码为"输入图片中指定颜色的文字"，服务按 HSV 颜色掩码提取字符后用 ddddocr 识别。后台常驻运行，查验期间勿关闭。用 `curl http://127.0.0.1:8731/health` 确认在线。

### 3. 批量查验

```bash
node scripts/check.mjs <工作目录> [from] [to] [结果文件名]
```
- 自动跳过已有终态结果（一致/不一致/查无此票/平台不支持/需补充数据）的票，可安全重跑补验。
- 预检自动处理：清空数电票误填的"伪发票代码"；区块链发票、纸质车票标记为"平台不支持查验"；无校验码的老式税控票标记为"需补充数据"。
- 结果写入 `<工作目录>/results.json`（分片时用第4个参数指定 results_A.json 等），截图存 `<工作目录>/screenshots/`。
- 大批量（>50张）建议后台运行并定期查看日志；**单 worker 串行**，不要并发多开（平台限流严格，并发会触发"访问过于频繁"并导致验证码接口停摆）。
- 限流/验证码未加载时脚本自动退避等待，无需人工干预。
- 首轮完成后统计临时失败，串行补验；默认最多追加两轮，仍失败则交付中期报告和待重试清单。中断后先检查原进程、结果文件和 OCR 健康状态，再决定续接或重启，保证仅有一个查验 worker。

### 4. 生成 HTML 报告

```bash
node scripts/report.mjs <工作目录>
```
生成 `<工作目录>/发票查验报告.html`：状态统计卡片、核心结论、全量明细表，每行可展开平台查验结果截图。查验未全部完成时标题自动标注"（中期）"。

### 5. 预览与交付

```bash
node scripts/serve.mjs <工作目录> 8765
```
启动静态服务后用 present_files 呈现 `http://127.0.0.1:8765/`。报告内嵌截图为相对路径，必须经 HTTP 服务预览（直接 file:// 打开截图不显示，但文件本身完整）。

## 结果状态约定

| 状态 | 含义 |
|---|---|
| 一致 | 平台返回完整发票详情，票面信息与底账库一致（真票） |
| 不一致 / 查无此票 | 票面信息与底账库不符或无记录（异常票，重点提示用户） |
| 超过每日查验次数 | 同一发票当日已查验5次，次日再试 |
| 平台不支持查验 | 区块链发票/纸质车票等不适用该平台 |
| 需补充数据 | 老式税控票缺校验码后6位，请用户补充后重跑 |
| 被限流待重试 / 验证码识别失败 | 临时性失败，重跑 check.mjs 自动补验 |

## 注意事项

- 每份发票每天最多查验5次，重跑前先确认失败原因，避免浪费次数。
- 用户若补充了校验码，更新 invoices.json 中对应记录的 checksumCode 字段后重跑即可（终态票不会重查，需补数据票会自动放行）。
- 按 `results.json` 的状态汇总结果；类型分布与代码是否为空属于不同维度，不可叠加成总数。“一致”只覆盖实际成功查验部分；平台不支持和需补数据仍未完成验真。
- 平台字段或选择器可能改版，若批量失败先用 `node scripts/probe_labels.mjs` 诊断表单结构，再对照 references/platform-notes.md 排查。
